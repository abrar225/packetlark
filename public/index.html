PacketLark is an independent, open-source side project for developers who want a small, understandable HTTP workspace. It stores its workspace locally and doesn't require a PacketLark account.

It’s early. It doesn’t replace Postman’s collaboration, protocol coverage, or automation platform. If a focused local workflow fits you, there’s something useful here.

A few things to know.

Is PacketLark a replacement for Postman?

For basic local HTTP requests, collections, and scripts, it may fit. For OAuth flows, gRPC, WebSockets, team collaboration, monitors, mock servers, or mature CI workflows, use a tool with those capabilities. PacketLark’s most interesting workflow is capturing HTTP traffic and inferring a spec.

Does the studio work without the internet?

The interface, fonts, icons, and workspace run locally after installation. Calling a remote API still requires a network connection. Collections and environment values are plain files, so keep credentials out of Git and only run scripts you trust.

What does the traffic proxy capture?

HTTP requests explicitly routed through it, including HTTPS targets using the /https://target path or X-Target-Url header. It doesn’t decrypt browser HTTPS CONNECT tunnels. Traffic is held in memory, capped at 500 records, and can contain sensitive data.

Can I contribute?

Yes. PacketLark is MIT licensed. Read the source, try it against your own API, and share an issue or a pull request on GitHub. Reliability, migration compatibility, and everyday usability are especially valuable contributions.
