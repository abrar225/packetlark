# P2 credential lifecycle and OAuth

`CredentialStore({workspaceId, metadataPath, provider?})` namespaces native entries with a SHA-256 workspace identity. Use the repository's canonical workspace identity and a dedicated private directory such as `.rea-api/private-credentials/metadata.json`. The directory must be owner-only (0700); metadata files must be regular owner-only files (0600). Ancestor symlinks, metadata symlinks, invalid schemas, unknown purposes, oversized metadata/values and foreign workspace metadata fail closed. Metadata uses bounded reads and exclusive private temporary files with atomic rename. Values are never written to this file. Treat filesystem protections as defense against other OS users; a compromised process running as this user can access the user's vault and filesystem.

`create({label,value,origins,storage:'session'|'keychain',kind?:'secret'|'oauth-client-secret'})` returns `{id,reference,label,origins,storage,kind}`. References have the exact form `{{secret:UUID}}`. `list()` returns metadata; `delete(idOrRef)` removes a value and its metadata. `resolve(ref, origin)` is an internal request-execution primitive, allowing only generic `secret` values bound to that URL's exact origin (scheme, host, effective port). `resolveClientSecret` permits only OAuth client secrets bound to a token/revocation endpoint origin. Neither accepts token bundles. Do not expose resolver return values through management APIs, logs, collection export or MCP results.

Session storage is an explicit user choice. Metadata can remain after restart, but resolving that session value fails until the user supplies a new credential. Native storage uses `@napi-rs/keyring`: macOS Keychain, a Windows Credential Manager adapter, and Linux Secret Service (required explicitly, with no kernel keyutils fallback). Native errors are replaced with generic errors; no plaintext fallback exists. The optional native dependency permits installation on unsupported machines; selecting native storage on them fails closed. Native calls do not spawn a process and values never enter argv. Windows persistent creation currently fails closed because private metadata ACL enforcement has not been implemented; explicit Windows session storage keeps both metadata and values in memory. Native Windows adapter existence is not a claim that persistence is supported or verified.

`OAuthService(store,{callbackUrl})` accepts only a fixed HTTP loopback callback on `127.0.0.1` or `::1`. The server owns that exact route, such as `/api/oauth/callback`; bind the HTTP server to loopback and route callback query strings only to `callbackForUrl(url)`. A different origin/port/path, state mismatch, denial, timeout, or consumed flow fails. Pending flows are bounded to 64, expire after five minutes, and contain PKCE verifier/state/nonce only in memory. `dispose()` clears pending timers.

`start(config)` returns `{flowId,authorizationUrl,expiresAt}`; `callback(flowId,url)` or `callbackForUrl(url)` returns new connection metadata. `clientCredentials(config)` returns connection metadata directly. Config fields: `label`, `issuer`, `authorizationEndpoint` (code flow), `tokenEndpoint`, optional `revocationEndpoint`, optional `jwksUri` (OIDC), `clientId`, optional `clientSecretRef`, `allowedOrigins`, `storage`, optional `scope`, `environment`, and `account`. Supply a dedicated client-secret reference for confidential clients; public authorization-code clients use no client secret. Every start creates a separate connection, including across environments/accounts. HTTPS is required for provider endpoints. The explicitly named `allowInsecureLoopbackForTests` option exists only for disposable localhost fixtures and must not be user configurable.

The maintained `oauth4webapi` implementation handles state, PKCE, token response parsing and OpenID claims/signature validation. If `scope` contains `openid`, an ID token with the expected nonce and a valid application-level signature is required; configure `jwksUri`. OAuth access tokens are opaque values, not homemade JWTs. Only Bearer token responses with positive finite `expires_in` are accepted. Provider redirects are rejected, wire requests have a 15-second timeout, response bodies are bounded to 128 KiB, and provider response details never enter thrown errors.

`token(connectionId,origin)` is an internal executor-only primitive that checks the API origin before returning an access token. Access/refresh token, expiry and sanitized config form one atomic vault value of kind `oauth-bundle`. Refresh happens within 30 seconds of expiry; concurrent calls share a single refresh, including ID/reference aliases. Rotated refresh tokens replace the previous bundle atomically; an omitted refresh token retains the previous value. Expired connections without a refresh token require reconnecting. `list()` returns metadata only. `clear(id)` removes local credentials without making a remote request. `revoke(id)` explicitly calls configured provider revocation for refresh/access tokens then removes local data; a remote failure retains the local connection for retry. Neither startup nor metadata listing creates grants or contacts third-party accounts.

Internal bundle methods (`createOAuthBundle`, `resolveOAuthBundle`, `replaceOAuthBundle`) exist only for OAuthService. Cookie persistence uses the distinct `cookie-bundle` purpose and internal `createCookieBundle`, `resolveCookieBundle`, `replaceCookieBundle` methods with the same argument shapes and 64 KiB value cap; cookies cannot resolve through generic or OAuth primitives. Management routes must never expose them. `clear` and generic credential delete can leave remote grants active; the UI should explain the explicit revoke action.

Verification uses disposable temp directories and a real local HTTP fake provider with seeded credentials. It checks purpose/origin/workspace restrictions, session restart behavior, metadata permissions/symlink rejection, native error redaction via an injected provider, PKCE wire parameters, callback failure/replay/timeout, refresh concurrency/rotation, revocation failure retention, local clear, response bounds and secret-free metadata/errors. Tests never read existing user credentials or use third-party accounts. The opt-in native check creates and deletes only a disposable entry. On macOS arm64, native create/read, independent-process restart resolution, origin refusal, metadata privacy and deletion passed; see `verification/P2_NATIVE_VAULT.json`. Linux Secret Service remains unverified, and Windows persistence is unavailable pending private metadata ACL support.

Metadata reads never create directories. Only explicit credential creation provisions the private directory. Metadata duplicate IDs fail closed; complete serialized metadata is capped at 1 MiB before native values are created. Successful rename is followed by a parent-directory sync when supported. The Studio workspace lease and headless execution lease must provide exclusive writer ownership across processes; store queues serialize within an instance. Explicit revoke blocks new token calls and waits for pending refresh before revoking the current rotated pair.

Safe export is a detached structural projection: sensitive JSON fields, raw JSON bodies, decoded URL userinfo/query fields and sensitive key/value pairs are redacted, while references remain inert. Known values and standard encoded copies elsewhere are then redacted. Arbitrary scripts, unknown free text and arbitrary cryptographic transformations cannot be automatically identified as secrets; review those before sharing. Migration scanner candidates cover structured fields, not every potential body/script value.

CLI `workspace snapshot` and `workspace backup --backup-file new.json` use the same safe export projection by default. Backups retain the repository envelope (`version`, SHA-256 `checksum`, serialized `payload`), with a new checksum computed over the redacted payload, so the restore preview validates them normally. Restoring a safe backup restores redacted placeholders, not the original inline credentials. References remain inert; no vault is read. Destinations are exclusive, owner-only files and existing backups are never overwritten.

Exporting plaintext requires both `--include-secrets --consent plaintext` on snapshot or backup. Either flag alone, or another consent value, fails before exporting. Treat the resulting terminal output/file as sensitive; no vault values are resolved even with these flags.

Migration and restore retain lossless internal recovery backups of the current workspace. Their previews report `recoveryBackup.inlineCredentialCandidates` and `plaintextBackupConsentRequired` without credential values. If the structured migration scanner finds inline credentials, `--apply` additionally requires `--consent plaintext`; this acknowledges plaintext in the retained recovery backup. These backups are never redacted, because doing so would lose recovery data. The scanner has the limitations described above; consent detection does not prove a workspace contains no other secrets. Restore output remains safely projected. Reviewed checksum and revision requirements continue to apply.
