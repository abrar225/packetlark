# Tabs, history, examples and environments

P1 opens independent request tabs by collection/request identity. Selecting another tab preserves the draft, editor subtab and owned response. A transport already started may finish in the background; its result cannot replace the selected tab's response. Closing a dirty/running tab requires explicit confirmation and cancels its execution. A pending save must settle before that tab can close. Arrow keys, Home and End navigate tabs.

There are at most 20 open tabs. Each retained response is at most 2 MiB, with a 16 MiB aggregate cap. Larger responses retain a bounded 64 KiB body preview and bounded assertion metadata with a visible warning. Old response previews expire before tabs/drafts are removed; selecting an expired preview explains why it is unavailable. These limits apply to the retained UI representation, separately from transport response limits.

Undo retains up to 20 previous request edits and 2 MiB per open request. It changes the unsaved draft, keeps identities and never writes canonical files automatically. Undo is page-local; acknowledged restart recovery uses the separate opt-in [draft recovery](WORKSPACE_DRAFT_RECOVERY.md) protocol. Recovery retains the original canonical revisions so a later save cannot silently overwrite newer disk data.

History is page-local, with at most 50 sanitized entries, 4 MiB total and 512 KiB per entry. It is discarded on navigation and never automatically replays requests. Inspect an entry before opening an unsaved copy. The copy receives a new request ID and writes to the collection only after Save. Discarding its tab removes the transient tree entry.

Save example opens a review preview first. Only **Save reviewed example** plus explicit confirmation writes IndexedDB (`packetlark-reviewed-examples-v1`) for the current browser origin/workspace identity. Examples survive reload, are capped at 20 / 4 MiB per workspace and 256 KiB per review, and can be explicitly deleted. Storage failures preserve the current dialog and report the error. A late read/save/delete cannot take over a newer dialog. Browser/host/port changes, browser data deletion and private-mode limitations apply; examples are not a canonical workspace backup.

The history/example projection excludes authentication, scripts, opaque import metadata, unknown headers and unstructured/binary bodies. It masks marked variables, known credential values and recognized sensitive JSON/query/form fields, including inherited execution context. Structured JSON remains parseable after masking. Arbitrary business fields can contain unknown secrets: users must review the displayed preview before persisting or sending it. This is explicit local storage, not encryption or a P2 credential vault.

Environment Management supports create, rename, edit, enable/disable, secret marking and delete with revision-checked writes. A failed save retains its local values and blocks Send until resolved/retried; a pending save finishes before execution captures the environment revision. Enabled environment values override collection/folder values, and runtime values override both. Disabled duplicates do not hide enabled ancestors; the last enabled duplicate in a scope wins. The editor explains this order and the plaintext limitation. Secret marking masks quick-look previews and reports; canonical local files still contain the value. Secure credential references remain P2.

Verification is recorded in [P1_WORKBENCH_BROWSER.json](verification/P1_WORKBENCH_BROWSER.json), the final recovery/regression records and `tests/workbench-state.test.ts`. Browser checks use disposable workspace roots and synthetic credentials only.
