# ADR: P2 native credential vault and standards OAuth

Status: accepted for P2 implementation.

Store reusable credentials in the operating system vault, separate from collection/environment JSON. Keep metadata in a private workspace directory; workspace hashes namespace native entries and references are UUIDs. Session-only storage is explicit and never an implicit fallback. Typed credential purposes prevent substituting a serialized OAuth bundle into an ordinary request field. Persist each OAuth connection's access/refresh/config/expiry as one native value to avoid partial refresh rotation.

Use pinned `oauth4webapi@3.8.8` (MIT), a maintained zero-dependency ESM OAuth/OIDC client implementation. Its official [repository and maintenance policy](https://github.com/panva/oauth4webapi) cover authorization code with PKCE, client credentials, refresh, revocation and OIDC. The [authorization-code example](https://github.com/panva/oauth4webapi/blob/v3.8.8/examples/oauth.ts), [OIDC example](https://github.com/panva/oauth4webapi/blob/v3.8.8/examples/oidc.ts) and [API reference](https://github.com/panva/oauth4webapi/blob/v3.8.8/docs/README.md) are implementation references. Node 22 meets its Node 20 baseline. Explicit configured endpoints avoid discovery changing approved endpoint bindings. OIDC signatures use the library's JWKS validation rather than application JWT crypto.

Use pinned optional `@napi-rs/keyring@2.1.2` (MIT for the Node binding), whose [official documentation](https://github.com/Brooooooklyn/keyring-node) documents native Entry APIs, supported platform binaries, Linux backend selection and bundled dependency notices. It wraps Rust native OS credential stores with [upstream keyring](https://github.com/hwchen/keyring-rs). macOS uses Keychain, the native Windows adapter uses Credential Manager, and Linux requires Secret Service explicitly. Persistent creation on Windows currently fails closed because Node mode bits do not enforce private ACLs; Windows session storage retains metadata only in memory. Private Windows ACL integration remains future work. The library's automatic Linux keyutils fallback is deliberately disabled because it is memory-only. Native import or backend failures produce generic errors and require an explicit choice of session storage. Linux binaries bundle libdbus under `AFL-2.1 OR GPL-2.0-or-later`; shipped platform packages include third-party notices. Binding MIT does not replace these dependency notices.

This avoids legacy unmaintained keytar and avoids macOS `security ... -w PASSWORD` subprocess argv exposure. No encryption key is embedded in the application, and no plaintext credential file is created. Node strings cannot be reliably zeroized; process memory remains part of the trust boundary. Injected providers exercise refusal and race paths. The opt-in disposable macOS native check also passed create/read, origin refusal, independent-process restart and deletion; see `verification/P2_NATIVE_VAULT.json`. Linux remains unverified; Windows persistence is explicitly unavailable until ACL privacy is implemented. The check never reads existing credentials or changes default keychain settings.
