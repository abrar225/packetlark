# Workspace authoring

`web/workspace-authoring.js` supplies a keyboard usable management dialog and row action buttons. Collection, folder and request create/rename/duplicate/delete, within-collection move/reorder, and collection/folder inherited settings all use conditional collection writes. Positions are zero based in the destination after removing the moved item. Empty collections remain selectable in the management dialog. Auth and variable JSON editors preserve unmodified opaque imported fields; scripts are plain text and are never evaluated in the UI.

Native drag-and-drop uses the same commands: drop on a request to insert before it, or on a folder/collection to append. A confirmation names the destination. The drag captures source/target revisions, rejects changed targets, cycles and affected dirty/running drafts, and preserves canonical state on failed writes. Cross-collection drops require manifest storage. **Actions → Move / reorder** remains available to keyboard users and for empty/offscreen destinations. [P1_DRAG_BROWSER.json](verification/P1_DRAG_BROWSER.json) records five real Ego drag gestures, including negative paths.

`src/core/workspace/CollectionCommands.ts` provides pure commands that clone before changing content, preserve stable identities during edits/moves, assign fresh collection/item/request identities throughout duplicates, reject folder cycles and validate the existing 24-level/10,000-item limits. Cross-collection Move calls `POST /api/workspace/move` with both reviewed collection revisions. Manifest workspaces commit source and destination atomically; legacy workspaces return an explicit migration-required conflict without mutation. The optional `moved({sourceCollectionId,destinationCollectionId,itemId,requestIds})` callback rehomes request tabs/drafts using the captured subtree request IDs. Cross-collection Copy is deliberately named separately and keeps the source intact while assigning fresh identities.

The constructor accepts `model()` with `{ collections, drafts, collectionSaves }`, `commit(collection, baseRevision, operation)`, `deleted(collectionId)`, `syncFields()`, `openModal()`, and `closeModal()`. `commit` inserts new collections as well as replacing existing ones. For `{atomicMove:true}`, publish both collections before pruning clean tabs; the `moved` callback then rehomes their identities and responses. `decorateRow(row,node)` appends a native Actions button; `open(collectionId?,itemId?)` opens the management dialog. The standard modal uses `#modal-title` and `#modal-body`. Expose a global Manage collections button even when the tree is empty.

Writes refuse collections with dirty/saving request drafts or existing pending saves, display a retry instruction, and retain drafts and form values. They reserve affected `collectionSaves` entries synchronously before transport; ordinary request saves must continue to queue on this map. Failed writes/conflicts release reservations and keep form input. Commit callbacks must preserve newer request drafts created while a write was pending. A deletion callback must recover any newer owned request drafts before closing their original collection selection.

Verification: `npx vitest run tests/authoring.test.ts` exercises pure identity/content/cycle/depth behavior, inherited execution context resolution, conflict preservation and save ownership. `scripts/check-p1-authoring.mjs` exports `verifyWorkspaceAuthoring(page,baseUrl)` for the existing Ego Page API disposable-server harness; it drives actual dialog controls and cleans up only the unique collections it created. Browser execution must be recorded separately; merely importing the harness is not runtime evidence.
