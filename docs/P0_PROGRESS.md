# P0 trust foundations — implementation and evidence

25 October 2026. **P0 remains in progress.** The user approved the plan and eight test interfaces in Q7. This record covers the first implementation bundle, not the full ten-workstream roadmap, a stable release or a new product rating.

## Implemented in this bundle

**Capture transport — TR-001/002.** Uploads remain bytes; inspection uses a separate bounded copy. A shared decoded-response reader serves execution and capture. Default capture limits are 4 MiB incoming body, 10 MiB decoded upstream body, 30-second total request deadline after headers, eight active forwards, 32 open sockets, 500 retained records, 32 MiB retained serialized history and 1 MiB per observation. Constructor options configure these limits. Admission failures return 503; oversized uploads 413; oversized decoded responses 502; active-request deadlines 504. Pre-header sockets also have Node header/inactivity timeouts and a bounded connection count. Redirects remain visible rather than followed. Hop-by-hop/control headers are removed; decoded response encoding/length headers are corrected; HEAD representation length is preserved. Disconnect, shutdown and blocked downstream writes release active work. This is bounded buffering, not a streaming transport or an SSE/HTTPS CONNECT client.

**Safe observations — TR-003.** Common credential field names, optional configured sensitive names, cookies, query values, form fields, JSON sensitive subtrees and known echoed values are redacted before retention and subscriber publication. Unknown headers are withheld; unstructured/binary inspection bodies are omitted. Redaction traversal/secret-budget failures omit the observation. Repeated form values and ordered query entries survive normalization. Subscribers and callers receive independent snapshots. Seeded credentials were absent from retained/subscribed observations and generated OpenAPI/client drafts while authorized forwarding still delivered the original credentials.

This is heuristic redaction, not universal secret detection or encryption. Unknown names, transformed/encoded fragments, sensitive values under innocuous keys and other logs/report paths remain review concerns. Query strings containing sensitive values are sanitized; path/field names can still carry information. Configured field names are currently an engine option, not a complete settings UI. The traffic screen shows actual capture budgets and omissions.

**Request ownership — TR-004.** Drafts belong to collection/request identities and keep a version. Switching requests preserves unsaved work in memory; unload warns about dirty drafts. A save marks only its captured version clean. Per-collection saves serialize and advance compatible draft baselines. A delayed or failed save cannot clean another draft. Selection cancels its outgoing execution, clears the prior response, and prevents late results/finalizers/metric callbacks from changing another selection. New requests use the returned collection revision. Confirmed deletion removes only its owned draft.

Environment autosaves serialize/coalesce without replacing newer editor input. Send waits for the selected environment's pending save and includes its revision; failed saves block Send. Execution uses an environment snapshot. No-op environment scopes are not rewritten; actual script changes commit against the execution's original revision. A conflicting/failed persistence outcome is returned separately in `response.persistence.environment`, preserving the HTTP result and exposing the warning in the console panel.

**Workspace integrity — TR-005/006.** Per-resource JSON files are authoritative. Legacy aggregate JSON is retained unchanged as a migration source; new saves do not maintain a second live mirror. Initialization markers distinguish intentional emptiness from a new workspace. Migration validates and preflights the complete source, journals a snapshot and resumes missing resources after interruption; differing existing files cause an explicit error. Serialization stays within the loader's 2 MiB resource limit, using compact JSON when indentation alone would exceed it.

Writes use an exclusive 0600 temporary file, file fsync and rename before changing in-memory state. Deletes report filesystem failures. IDs and known nested resource/request/variable structures are validated; malformed or oversized canonical files fail explicitly instead of being hidden or replaced with samples. List reloads reconcile removed files. Resource revisions are content hashes; the workbench sends `If-Match` for edits/deletes, and stale revisions return 412 `ERR_WORKSPACE_CONFLICT`. Duplicate create IDs return 409. Direct API clients that omit `If-Match` retain legacy server-snapshot behavior; they do **not** get full stale-client protection.

Arbitrary external editors can still race between the hash check and rename. There is no cross-process workspace lock, atomic multi-resource transaction, directory-fsync/power-loss certification, automatic merge, file watcher or durable browser-draft recovery. Those stronger workspace capabilities remain P1 work. Bad existing files require repair/restoration; this implementation deliberately preserves them for recovery.

**Script scope contract — TR-007, documentation only.** The Scripts panel now states the actual policy: Send persists environment script changes if their revision still matches; collection/global/local mutations are returned with the response. Runs keep scope mutations within the run. Variable writes and iteration data currently use strings. Typed values, fuller `pm.request` semantics and pinned differential compatibility remain P3 work.

## Observed verification

- `npm run check`: build plus **98 tests in 15 files passed**. New public capture/workspace tests cover byte equality, declared/chunked upload limits, compression expansion, slow upstream and blocked downstream deadlines, open-socket/concurrency admission, disconnect/stop/restart, redaction and mutation isolation, seeded-secret draft exports, intentional emptiness, write failure, stale/external revisions, corruption, concurrent execution/environment updates, interrupted migration, expanded-format size and malformed nested data.
- Red/green demonstrations were observed for the binary/limit/redaction/deadline/HEAD/query-order/connection bugs, stale revisions, lost updates and migration cases. Additional negative-path coverage was added after implementation; it is not misrepresented as an observed initial failure.
- Permission-failure coverage uses a real non-root POSIX workspace; that case is skipped on Windows/root. Migration recovery separately injects a failure at `fs.renameSync`, the agreed filesystem adapter boundary, after one canonical resource commits.
- Ego browser: all **16 cases across five public UI harness groups passed in one final run**. `scripts/check-p0-browser.mjs` exports `verifyPendingEnvironment`, `verifyCreateDelete`, `verifyOwnership`, `verifyEnvironmentOwnership` and `verifyStaleDeletes`. The final traffic budget and script policy were visible. This is targeted desktop workflow QA, not a completed accessibility/mobile/editor-host matrix.
- `npm run build:extension`: strict extension compilation and bundle passed. Installed extension-host execution remains unverified.
- `node scripts/assessment-probes.mjs`: earlier query/auth/text/falsy/multi-origin regressions remained fixed.
- `node scripts/package-smoke.mjs`: a fresh production-only tarball installation executed the WASM script and CLI without source/dev dependencies.
- `npm audit --audit-level=high`: zero reported vulnerabilities. No new runtime dependency was added. This is not an independent security audit.

Browser reproduction: run `npm run build`, then `node scripts/p0-browser-fixture.mjs`. It prints a fresh URL and uses disposable storage. Through the documented Ego Page API, import the harness by its absolute file URL and run the five exported groups against that URL, with `verifyPendingEnvironment` first on a fresh fixture. Finish the task space and stop the fixture afterward. No live `.rea-api` data is used. No external API request is needed.

The loopback reference is [P0_BASELINE.json](verification/P0_BASELINE.json), measured at source `bf4398d` on Node 24 / Apple M4. Two hundred measured samples per path followed twenty warmups: direct response p95 0.163 ms; bounded capture p95 0.591 ms; workspace list p95 0.667 ms. Sampled RSS reached 162.81 MiB across the combined benchmark client, target, studio and two proxies. This is a single-machine sequential 1 KiB fixture, not production load, cold startup, browser responsiveness or a comparison with Postman. Run `npm run build` then `node scripts/benchmark-p0.mjs` to reproduce a new observation.

## Remaining P0 and release gates

Complete the wider threat model and adversarial export/log/agent/script data-flow review; test larger concurrent bodies, slow headers, repeated cancellation, long-duration retention and executor/capture policy consistency. Record browser responsiveness and cold-process baseline measurements, then ratify realistic performance budgets. Keep security review distinct from the implementation reviewer and advisory scan.

P1 must add durable drafts/recovery, explicit conflict-review/merge UX, workspace locking/watching and complete collection authoring. P2/P3 still own secure local secrets, OAuth/PKCE, richer HTTP settings, typed scopes, grants and demonstrated script compatibility. The remaining protocols and platform capabilities stay on the approved roadmap. No automatic stable release or parity/rating increase follows from this bundle.

VERDICT: PASS

This verdict covers only the observed checks listed here. P0 and the overall program remain open.
